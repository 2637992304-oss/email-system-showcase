# 我的个人贡献

## 角色定位

我在团队项目中主要参与数据库设计、后端接口开发与前后端联调，同时使用 Git 完成分支协作和问题修复。以下内容用于明确我的实际参与范围，不将团队整体成果表述为个人独立完成。

## 1. 数据库设计

- 根据用户、邮件、收件关系、附件、联系人和垃圾检测等业务对象梳理实体关系。
- 参与核心表结构、字段类型、主外键关系和基础约束设计。
- 绘制并维护 E-R 图，使后端开发能够按照统一的数据模型实现接口。
- 结合常用查询场景考虑索引和状态字段，减少后续接口调整成本。

## 2. 后端接口与数据访问

- 参与 Spring Boot 后端模块的接口设计与实现。
- 使用 MyBatis 编写部分数据访问逻辑和 SQL。
- 按 RESTful 风格组织接口，并配合统一响应结构完成前后端数据交互。
- 参与 JWT 登录认证相关流程的理解、调试和接口验证。

## 3. 前后端联调

- 使用 Postman 验证请求参数、身份认证、响应状态和返回数据。
- 根据浏览器请求信息和后端日志定位接口路径、字段名称及数据格式不一致的问题。
- 与前端成员确认接口约定，修复联调过程中发现的异常情况。

## 4. 团队协作

- 使用 Git 分支管理个人改动，通过提交记录保持修改范围清晰。
- 参与代码合并和冲突处理，避免覆盖其他成员的工作。
- 在提交前检查配置和测试数据，减少密码、密钥等敏感信息进入公开材料的风险。

## 5. 学习与问题解决

项目开发过程中，我会主动阅读 Spring Boot、MyBatis、JWT 和接口调试相关文档，并通过小范围验证确认理解。面对不熟悉的问题时，我通常按照“复现问题、检查请求与日志、缩小范围、验证修复”的步骤处理，而不是只停留在表面现象。

## 可在面试中重点说明

- 为什么将邮件主体与用户收件状态分开建模。
- JWT 在前后端请求链路中的传递与校验流程。
- RESTful 接口与统一响应结构如何降低联调成本。
- 如何通过日志、接口测试和数据库查询定位联调问题。
- 多人协作中如何控制提交范围并处理代码冲突。
